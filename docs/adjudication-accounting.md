# Protected adjudication accounting

`createAccountedAdjudicator` joins the protected final adjudication callback to a `PhaseAccountingObserver`. It receives no repair callback and performs no provider fetch, budget approval, retry or ledger reconciliation. Root composition supplies the actual check transport and the external evaluator workspace separately.

```ts
const adjudicate = createAccountedAdjudicator({
  sourceDigest, executionMode, publicEpisodes, reservationForExecution,
  observer, adjudicate: protectedAdjudication, saveCheckpoint,
});
```

`publicEpisodes` and `reservationForExecution` come from the session's validated public projection. The wrapper binds the adjudication dispatch/task/fixture identity to that projection and the reservation's opaque fingerprint, stage and amount. Its request fixes `phase: 'adjudication'` and the source, plan, model and policy digests. Files and oracle identifiers are forwarded only to the protected callback; neither appears in accounting checkpoints or observation requests. No verdict or check details return to runtime.

`saveCheckpoint` must synchronously persist the supplied `AdjudicationAccountingCheckpoint` before returning. The wrapper records each operation intent/handle before forwarding `onOperation`, and every cumulative USD/CPU observation before forwarding `onUsage`. The sink accepts only metadata: binding, selected artifact/public input digests, operation IDs, known lower bounds, state and checkpoint digest. The sink must be private, durable and append-preserving; an in-memory sink satisfies unit tests only. Sink failure stops progress and cannot authorize a side effect. The failed-state marker is attempted without exposing private persistence errors; if the sink itself fails, only checkpoints already successfully persisted can be claimed. This module does not pretend to implement the surrounding operator's durable store.

When the protected callback completes, the wrapper freezes its operation inventory and saves a finalized checkpoint. Here `state: 'finalized'` means the inventory is fixed before observation; accounting may still be incomplete, fail or time out. The outer composition must finish its trace only after the wrapper settles, preserving a later failed checkpoint. The observer receives that exact checkpoint digest, phase binding, operation set and cumulative lower bounds. Only an observation with the same checkpoint and exact inventory, a receipt digest, nonregressing values, and all five flags (`billingComplete`, `cpuComplete`, `inventoryComplete`, `cleanupComplete`, `retentionFinal`) can expose measured USD and CPU in the returned aggregate. Incomplete observations return null totals while preserving known values through `onUsage`; mismatched observations fail closed. The observation receipt remains bound to the original finalized checkpoint even if its complete measured totals exceed the original lower bounds.

The wrapper uses the dispatcher's remaining adjudication timeout for both checks and the accounting wait. Cancellation or expiry cannot extend this deadline. A callback ignoring cancellation is abandoned by the wrapper; this is not proof that a remote operation stopped. Existing handles and the failed checkpoint remain for explicit cleanup and reconciliation. Post-deadline callbacks cannot rewrite a terminal dispatcher row. Any later cleanup usage must remain in the protected transport's raw private evidence for explicit reconciliation; this wrapper cannot retrospectively establish a complete total. The actual protected transport must enforce prospective resource ceilings and retain remote intents before side effects. Hash equality records integrity, not provider billing or execution authenticity.

`AdjudicationInput.onUsage` is optional for existing adapters and reports **cumulative within adjudication**, including setup, retries, cleanup and retention. The dispatcher combines each phase report with immutable finalized runtime usage once. Thus runtime $0.10, adjudication $0.02, then adjudication $0.03 means $0.13 total. A later null does not erase a known lower bound; a lower numeric total is rejected. Checkpoints are accepted only while this owner remains actively adjudicating. `AdjudicationInput.onFinalUsage` uses the same cumulative shape after paid adjudication work is quiescent. It records a completed observation even when that observation proves an overrun, retaining charges and the sticky ledger freeze; it grants no further work. Later prospective `onUsage` callbacks are refused. The wrapper uses this final callback after its protected callback settles and for accepted observation totals. A trusted protected transport may call it earlier only after all paid work and cleanup are quiescent; later prospective usage cannot reopen work. The final aggregate controls completeness, while failure/cancellation exports null totals, durable usage retains the known bound, and the existing ledger keeps its unknown-billing hold. This change does not loosen the known-runtime-USD/CPU gate before adjudication.

The dispatcher alone persists usage to its existing ledger checkpoint path. This wrapper never imports whole-episode accounting receipts or releases a reservation. An operator must reconcile unresolved billing explicitly after remote work and retention are accounted for. The process-local one-use check complements the dispatcher's durable finalized selection and the protected evaluator's durable one-use record; it does not replace them after restart.

Tests use invented metadata, empty inert artifact maps and callback-only transports. They do not run candidates, inspect a corpus, call a provider or spend money. The concrete live composition and durable checkpoint sink remain separate integration responsibilities.
