# Two-minute judge demonstration

Open <https://patchproof.andrewmohawk.xyz/>. This route reviews saved real executions and does not generate a new patch. Keep the browser on the walkthrough until the final step.

1. **The bug.** “You maintain a small Python library. This function should keep each item once, in its original order. It leaves the second elm in the output. PatchProof proposes a repair and checks it against requirements the model cannot edit. You still decide whether to use it.” Point to the wrong and required outputs, then select **See the AI patch**.
2. **The proposed change.** “The old function compared only neighboring items. This patch looks through all items already kept. The output now removes the duplicate. A plausible explanation is not the pass criterion: PatchProof executes the checks.” Select **See the check results**.
3. **The decision.** “The original code passed five of nine checks; this patch passed all nine. The checks cover duplicate removal and order, preserving the caller's data, and the existing TypeError for None input. This is evidence for those requirements, not a guarantee for every input. A developer should inspect the patch and exact checks before applying it.” Select **See a repair that failed**.
4. **A failed repair.** “This is a separate worksheet task. The function should swap rows and columns while keeping a null cell empty. The candidate replaces it with 9. Eleven of thirteen checks pass, but the patch is not approved. Later attempts had execution errors, which remain in the record.” Select **Inspect the failed checks** to show the actual expected and observed values.
5. **What the reviewer receives.** Open the successful run from the walkthrough's **Inspect patch and checks** link. “The reviewer gets the source diff, requirements, observed results and a downloadable run record. Nothing is merged automatically.” Download evidence if useful. Replay needs the source checkout and environment recorded by the run; public source distribution is still a separate project decision.
6. **The interactive path.** Select **Try a repair**. “These are twenty curated Python tasks. Generate patch asks the live Nebius Token Factory model for a new proposal, checks it in local Docker containers, and opens the result for review.” Starting a run uses the project owner's approved allowance; it is optional during the two-minute explanation.

Do not call the local containers Nebius-hosted Sandboxes, describe these development runs as a benchmark, imply support for arbitrary uploaded repositories, or claim a passing test suite proves all inputs correct. The recording and walkthrough demonstrate real saved executions; a new live run is a separate action.
