# Interface redesign

The owner requested a complete usability and copy redesign, with multiple UX/UI agents discussing the approach and an independent review for AI-style filler. The public app continues to use real Token Factory inference and local Docker checks; this change does not claim a new evaluation result.

Three reviewers inspected the real service, discussed tradeoffs, and agreed on Examples/Runs navigation, an immediately visible Generate patch action, searchable examples, latest results including failures, and Patch/Checks/Activity/Run details tabs. Their initial reviews and resolved disagreements are in ux-review.md, visual-review.md, and copy-review.md. The copy reviewer independently rejected the first implementation and approved it only after five concrete issues were fixed.

Changed operational files: apps/web/index.html, style.css, app.js, verify-browser.ts and scripts/record-public-demo.ts. The existing API, repair policies, provider limits, saved run bytes and evaluator remain unchanged. Display summaries require exact public source/policy digests, and historical results still bind their requirements to their saved bundles.

Browser checks cover all twenty examples at desktop, 390px and 320px, saved successes/failures/incomplete runs, budget/cancellation controls, task search, keyboard navigation, SSE refresh focus and disclosure preservation, comparison task selection, and immutable historical context. The mobile primary action moved from below y=1800 to within the first viewport on every example. See visual-final-review.md, copy-final-review.md and their JSON/screenshot evidence.

The initial full suite ran 679 tests: 678 passed and one shell-copy assertion still expected the removed loading text. The assertion was updated to the new neutral Connecting status, and its focused rerun passed. Final suite, actual local Docker browser integration, public deployment and updated video receipts are recorded below after completion. Synthetic UI tests and mock-inference local checks are verification mechanisms; they are not substituted into the public live service or recording.

No paid model requests are needed for this interface change. Recorded real-model runs remain available with their original provenance, including failed runs. The new walkthrough will explicitly review saved results without claiming new inference.

The subsequent concurrent full suite ran 680 tests: 679 passed, with the existing real-Docker abstention test reaching its 30-second runtime ceiling while the separate full browser integration was also creating containers. The failed status was infrastructure_error, never a false patch pass. Its log is preserved in verification/test-concurrent.log; the final suite is rerun without the competing integration workload. The first actual browser integration produced all three passing recorded variants, then failed its observer-only generic Tab assertion; the assertion now verifies the specific mobile picker-to-Generate-patch transition. That failed observer log is also preserved.

Final validation: `node --test --test-concurrency=4 tests/*.test.ts` exited 0, **680/680 passed** in 77.3 seconds. `npm run typecheck`, the 10 focused live UI tests, 5 recorder tests, and `npm run test:browser` all exited 0. The latter produced three passing mock-inference/real-Docker runs and a verified evidence download; see verification/local-browser-receipt.json. Playwright 1.58.2 / Chromium 145.0.7632.6, Node 25.5.0; dependencies remain pinned in package-lock.json. Staged redacted gitleaks scan reported no leaks. No paid requests were made for these checks.
